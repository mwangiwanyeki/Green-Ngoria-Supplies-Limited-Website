# UX.md --- Green Ngoria Supplies Limited

## Enterprise Mining, Plant Engineering & Construction UX

### 1. UX mission

The platform must turn Green Ngoria's complex mining and engineering
services into a connected digital operating workflow.

Primary experience: **Discover → Qualify → Assess → Engineer → Quote →
Contract → Build → Commission → Operate → Maintain**

The profile emphasizes client satisfaction, quality, engineering
expertise, construction supervision and personalized service.

### 2. UX priorities

1.  Mining/project conversion
2.  Technical credibility
3.  RFQ and quotation efficiency
4.  Project transparency
5.  Engineering document control
6.  Procurement visibility
7.  HSE and commissioning traceability
8.  Asset and maintenance continuity
9.  Strong admin control

### 3. Public website journey

**Home → Mining Capability → CIP/CIL Expertise → Plant Engineering →
Projects → Equipment → Plant Assessment → Consultation → RFQ**

Primary CTAs: - Request Plant Assessment - Discuss Mining Project -
Request Quote - Explore Equipment - Book Consultation

### 4. Mining lead qualification

Capture progressively: - name/company - role - project type - mining
location - mineral - project stage - estimated processing requirement -
existing plant - key challenge - expected timeline - budget range where
appropriate - contact details

Do not ask for complex engineering data before establishing basic
context.

### 5. Technical Plant Assessment UX

Guided workflow: 1. Project information 2. Mining/site location 3.
Mineral/ore information 4. Existing plant 5. Process flow 6. Equipment 7. Production/performance 8. Utilities 9. Operational challenges 10.
HSE/environment 11. Attachments 12. Review and submit

Features: - autosave - progress indicator - draft state - validation -
document upload - mobile-friendly forms - secure attachments -
assessment reference - confirmation - follow-up scheduling

### 6. Assessment result UX

After submission show: - reference number - received status - assigned
team/next step where available - expected response process - secure
document status - contact option

Do not automatically promise engineering recommendations or turnaround
times unless configured by the business.

### 7. CRM UX

Pipeline: **New → Qualified → Consultation → Assessment → RFQ →
Quotation → Negotiation → Won/Lost**

Every lead/opportunity: - owner - source - organization - contact -
estimated value - project type - location - stage - next action -
next-action date - activity timeline - linked assessment/RFQ/quotation

### 8. Equipment and RFQ UX

Equipment discovery: **Category → Equipment → Technical Details →
Datasheet → Add to RFQ**

RFQ: **Customer → Items → Quantities → Technical Requirements →
Attachments → Delivery → Review → Submit**

Allow: - save draft - duplicate RFQ - revision - clarification -
attachments - communication - status tracking

### 9. Quotation UX

Quotation header: - quote number - customer - project - issue date -
validity - status

Content: - equipment/services - quantities - unit price - taxes/fees -
totals - technical notes - exclusions - commercial terms - delivery -
warranty - attachments

Workflow: **Draft → Internal Review → Approved → Sent → Viewed →
Accepted/Rejected → Converted**

Keep revision history.

### 10. Client portal

The portal must answer immediately: - What is my project status? - What
needs my approval? - What documents changed? - What quotation is
active? - What payments are outstanding? - What procurement items are
pending? - What is happening on site? - What commissioning actions
remain? - How do I request support?

### 11. Project UX

Project navigation: **Overview → Timeline → Milestones → Tasks →
Engineering → Documents → Procurement → Construction → HSE → Inspections
→ Commissioning → Finance → Assets → Support → Activity**

Project phases: **Award → Planning → Engineering → Procurement →
Construction → Installation → Commissioning → Handover → Support**

Each phase: - owner - planned dates - actual dates - progress -
dependencies - risks - issues - approvals - documents

### 12. Engineering UX

Controlled documents must show: - document title - document type -
project - revision - status - author - reviewer - approver - dates -
related equipment - download/access rights

Revision example: **Rev 00 → Rev 01 → Rev 02 → Approved**

Never silently overwrite controlled engineering documents.

### 13. Procurement UX

Workflow: **Need → Requisition → Approval → Supplier RFQ → Supplier
Quotes → Comparison → Selection → PO → Delivery → Receipt**

Comparison should emphasize: - price - technical compliance - lead
time - supplier - payment terms - availability - exceptions

### 14. Construction/site UX

Site users need fast workflows: - daily report - activity - progress -
labor/workforce - equipment - materials - photos - HSE observation -
incident - inspection - NCR - punch list

The company profile states that safety is a priority and that EHS
performance is managed through objectives, training, participation and
continuous improvement. fileciteturn6file3L343-L357

### 15. Commissioning UX

Workflow: **System → Pre-check → Test → Result → Evidence → Exception →
Retest → Acceptance**

Support: - checklist - readings - evidence/photos/documents - failed
tests - punch-list links - approvals - sign-off

### 16. Asset/maintenance UX

Asset: **Identity → Serial → Project → Location → Status → Installation
→ Warranty → Documents → Maintenance → Service History**

Maintenance: **Issue → Work Order → Assignment → Parts → Work →
Verification → Close**

Support: **Ticket → Diagnosis → Action → Resolution → Customer
Confirmation → Close**

### 17. HSE UX

Provide: - observation reporting - incident reporting - inspection
checklists - corrective actions - responsible person - due date -
escalation - evidence - closure approval

Sensitive HSE information must be access-controlled.

### 18. Finance UX

Staff: - contracts - milestones - invoices - payments - balances -
reports

Clients: - authorized invoices - payment status - due dates - receipts -
payment history

Never expose internal financial information across organizations.

### 19. CMS UX

Admin can manage: - pages - services - mining capabilities - equipment -
spares - projects - case studies - technical insights - FAQs - media -
SEO metadata - navigation - CTAs

Use drafts, preview, publishing and revision history.

### 20. Global search

Search: - clients - contacts - projects - mining sites - assessments -
equipment - RFQs - quotations - contracts - documents - vendors -
assets - invoices - support tickets

Results must display type and context.

### 21. Notifications

Each notification should answer: **What happened? Why does it matter?
What must I do? By when?**

Examples: - Technical assessment requires review. - RFQ clarification
received. - Quotation awaiting approval. - Engineering revision requires
review. - Procurement delivery delayed. - HSE corrective action
overdue. - Commissioning test failed. - Warranty is approaching
expiry. - Maintenance work order overdue.

### 22. Permissions UX

Use least privilege.

Roles may include: - Super Admin - Admin - Managing Director -
Director - Legal - Production Manager - Project Manager - Mining/Process
Engineer - Mechanical Engineer - Electrical/Instrumentation Engineer -
Procurement Officer - Finance Officer - HSE Officer - Site Supervisor -
Sales/CRM Officer - Customer Care - Client Admin - Client Member

Role names must be configurable and mapped to actual company
responsibilities.

### 23. Cross-system continuity

The strongest UX feature is continuity:

**Lead** ↓ **Consultation** ↓ **Plant Assessment** ↓ **Opportunity** ↓
**RFQ** ↓ **Quotation** ↓ **Contract** ↓ **Project** ↓ **Procurement** ↓
**Construction** ↓ **Commissioning** ↓ **Asset** ↓ **Maintenance** ↓
**Support**

Never force staff to re-enter the same client/project information.

### 24. East Africa context

The company profile describes operations/interests across Kenya and
Tanzania and broader East/Central African experience.

Design the platform for regional operations: - country - county/region -
site - project location - local contacts - currencies - tax
configuration - logistics/delivery context

Do not hard-code Kenya-only assumptions into the core domain model.

### 25. Legacy supporting services

The UX can support secondary categories: - civil works - building -
roads - water - mechanical - electrical - timber - petroleum - general
supplies

However, navigation, homepage hierarchy, SEO and conversion flows must
clearly prioritize **mining and mining-plant engineering/construction**.

### 26. Error/recovery UX

Prefer: \> We couldn't submit the assessment. Your draft is still saved.
Please try again.

Over: \> 500 Internal Server Error

Always preserve user-entered data where possible.

### 27. Accessibility and responsive UX

All workflows must support: - keyboard navigation - screen readers -
visible focus - sufficient contrast - accessible forms - accessible
tables - reduced motion

Mobile should prioritize: - project status - approvals - forms - HSE -
site reports - documents - support

### 28. AI/automation boundaries

AI can assist with: - lead qualification - document classification -
summarization - search - notification prioritization - report drafting -
equipment matching - assessment triage

AI must not silently issue: - certified engineering designs - legal
conclusions - regulatory approvals - guaranteed mineral recovery -
guaranteed production - safety clearance

Human professional approval remains required for engineering-critical
decisions.

### 29. UX quality gate

Before release verify: - clear next action - correct role permissions -
cross-system continuity - technical credibility - accessibility - mobile
usability - performance - error recovery - auditability - privacy - no
fabricated company claims
